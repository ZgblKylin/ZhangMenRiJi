做一个 Web 游戏：《掌门日记》——武侠门派经营模拟器

游戏概念：
玩家是一个新立门派的开山掌门。游戏核心循环是"以月为单位推进时间，每月做几个关键决策，门派状态随之演化"，目标是把一个三流山寨经营成名震江湖的大派。

必须包含的元素：
- 至少 3 项门派属性（如声望、银两、士气，命名要有武侠味，不要用"等级""经验值"这种游戏术语）
- 弟子系统：弟子有姓名、属性、武学专精、忠诚度，可招募、可外派、会成长也会叛逃
- 弟子行动：包括研读书籍、同门传授、切磋、打熬气血、修炼内力、外派办事、江湖历练等。
- 每月随机事件：既有「邻派挑衅」「朝廷封赏」「弟子走火入魔」这类江湖事件，也要有「米价上涨」「掌门腰疼」这类生活流事件
- 武学体系：自创至少 5 门武功
- 一个简单的「年终论剑」结算
- 存档：浏览器内可保存进度

弟子属性体系：
武学属性复刻侠客行mud的设计，即天赋属性包含膂力、悟性、根骨、身法、福源，其他常见属性包括气血、精神、内力、精力、造诣、声望、道德、门忠、年龄。
侠客行mud中的经验改成造诣，去除潜能值，消耗潜能的行动改为当前设计的基于月为单位的回合制时间消耗。

气血：
35岁前，最大气血随年龄增长。35岁后，最大气血随年龄下降。增长和下降均使用与年龄相关的固定值，而非百分比值。
可通过根骨、最大内力、奇遇、药物、特殊功法等手段提升最大气血上限。
受伤、练功、历练、切磋等行为会消耗气血值，气血值为 0 时，弟子为重伤状态，无法进行任何行动。
最大气血小于 1 时，弟子死亡。
优先参考侠客行mud的设计。

精神：
35岁前，最大精神随年龄增长。35岁后，最大精神随年龄下降。增长和下降均使用与年龄相关的固定值，而非百分比值。
可通过悟性、最大精力、奇遇、药物、特殊功法等手段提升最大精神上限。
最大精神小于 1 时，弟子死亡。
阅读、学习、冥想、修炼等行为会消耗精神值，精神值为 0 时，弟子为昏迷状态，无法进行任何行动。
优先参考侠客行mud的设计。

内力/精力：
优先参考侠客行mud的设计。

造诣：
即侠客行mud中的经验值，优先参考侠客行mud的设计。
移除潜能值，消耗潜能的行动改为当前设计的基于月为单位的回合制时间消耗。

弟子行动：
弟子每月会自动行动，门派日志中需要简略描写行动内容和成果，包括但不限于：
- 研读书籍：研读门派藏书阁有的公共书籍，和自己收集的私有书籍，能够根据悟性和武学造诣提高对应武学经验
- 同门传授：直系师长，或者关系好的同门之间传授武学
- 切磋：与同门，或者历练时遇到的随机中立/友好对象切磋武学
- 打熬气血：门内修行，提升血量上限
- 修炼内力：门内修行，提升血量上限
- 外派办事：外派处理门派事务，提升门派声望，并为门派赚取银两，时间不定，结束前无法回归门派并继续其他活动
- 江湖历练：自由发挥弟子历练过程中的遭遇，时间不定，结束前无法回归门派并继续其他活动

门派相关：
- 人员体系：根据弟子的功绩和武学考核，分为长老-内门-外门-杂役四个级别。
- 职能部门：传功、掌书、药师、司库、内勤、外务
- 门派属性：声望、库银、道德
- 门派建筑：藏经阁、银库、药库、内门仓库（其他武学相关如兵器等）、外门仓库（生活事务、外门杂物所需）等等
职能和建筑可根据具体设计要求进行调整

武学体系/战斗体系：
完整沿用侠客行的架构，如基础技能、高级技能、消耗气血打坐修炼内功、消耗精神冥想修炼精力。

## 后续迭代需求

### 技术架构升级

**前端技术栈**：前端从原生 HTML/JS 迁移至 Vue 3 + Vite + TypeScript + Tailwind CSS v4。组件化开发，类型安全，构建产出由后端静态文件服务统一托管于 localhost:3000。所有界面组件均为 Vue SFC（单文件组件），样式优先使用 Tailwind 工具类，辅以组件级 scoped CSS。

**后端技术栈**：采用 Rust + axum 0.8 作为 HTTP 框架，sqlx 0.8 作为数据库驱动。业务逻辑集中在 `/logic` 模块（门派经营、弟子养成、世界事件、月度推进等），数据模型集中在 `/models`，数据库操作集中在 `/db`，HTTP 路由和 handler 集中在 `/handlers` 与 `/router`。代码改动严格通过 Codex 执行，禁止人工直接编辑源文件。

**数据库**：初始使用 PostgreSQL 18（JSONB 存储游戏状态），后因单机桌面游戏场景无需 Client-Server 数据库，且存档列表查询因全量拉取 JSONB 导致 2.38s 延迟，最终迁移至 SQLite。SQLite 为嵌入式单文件数据库，零部署依赖，存档列表查询优化至 80ms。连接信息通过环境变量 `DATABASE_URL` 注入（格式 `sqlite://<path>`），默认数据库文件路径为 `zhangmenriji.db`。

**窗口尺寸**：固定适配 1600×900 分辨率，三栏自适应布局，不依赖视口宽度做响应式断点。字号策略为 `html { font-size: clamp(16px, calc(14px + 0.25vw), 20px) }`，在宽屏上自然放大，保证可读性。全局强制浅色主题，通过 `color-scheme: light` 及 `!important` 屏蔽操作系统/浏览器的深色模式覆盖。

### v3.0 数据架构

游戏状态数据模型升级至 v3 版本（`schema_version: 3`），向后兼容旧存档的自动迁移。

**持久化**：前端废弃 LocalStorage，全部数据通过 REST API 与后端交互。每次存档创建/更新时，完整游戏状态序列化为 JSON 存入数据库 `state` 列。读取时从数据库反序列化并重建内存结构。

**多存档槽位体系**：引入 `save_group_id`（UUID）概念——一个槽位代表一局游戏（同一门派从创建到结局），槽位内可有多份存档（不同时间点的快照）。存档分两种类型：`auto`（每月推进自动生成）和 `manual`（玩家手动保存）。自动存档上限为每个槽位 10 份，超出后自动清除最旧的自动存档；手动存档不受数量限制。

**存档卷宗界面**：档位按槽位分组展示，每个槽位显示门派名称、当前年月、最近更新时间，展开后显示该槽位下所有存档列表（按更新时间倒序）。当前正在游玩的槽位标注「今」字印记。

### 三栏界面重构

将旧版双栏布局重构为左-中-右三栏案牍式布局：

- **左栏（左页）**：门派基本信息（名称、声望、银两、道德、本月剩余决策次数）与弟子名录。弟子以折叠卡片形式排列，折叠态显示姓名、等级、简要状态；展开态显示完整属性面板与武学技能列表。
- **中栏（中页）**：门派经营核心操作区。顶部为建筑标签页（百草堂、藏经阁、庶务堂等），切换不同建筑的管理界面。建筑页面包含委派长老、炼丹/制药、督造扩建、武学管理、物资调配等功能。中栏需独立垂直滚动，不可溢出至左右栏；所有子页面使用 `overflow-y: auto` 和 `min-height: 0` 保证 flex 容器内正确滚动。
- **右栏（右页）**：江湖纪事。分流展示三类事件：门派事件（弟子行动成果、建筑产出）、世界事件（NPC 门派动态、江湖传闻）、月令交互事件（需要玩家抉择的弹窗事件）。纪事按月份分组，最新在上。

**过月按钮**：位于中栏顶部右侧，与「本月尚可定夺 N 次」文本同行、整体靠右对齐、贴右边缘。按钮文案为「推演下月」，无箭头符号。

### 武学体系深化

**门派三层武学静态体系**：每个 NPC 门派拥有三层武学——杂役层（入门基础，多为粗浅拳脚）、外门层（进阶武学，含兵器）、内门层（镇派绝学，仅内门弟子可习）。三层武学以静态模板定义（`SECT_MARTIALS`），不在运行时随机生成。玩家门派的武学通过「武学研究」决策逐步解锁。

**武学等级与技能经验系统**：弟子的每门武学拥有独立等级（1-100 级及以上），通过修炼、阅读、切磋、同门传授等行动获取经验值。经验值按武学类别和弟子天赋（悟性、根骨等）加权计算。等级影响武学威力和相关属性加成。

**弟子六类技能属性面板**：弟子技能按门类分为拳脚（Unarmed）、轻功（Dodge）、内功（Force）、招架（Parry）、兵器（Weapon）、知识（Knowledge）六类。每类可装备/准备一门对应武学。知识类为基础武学，限定为门派基础心法，不可更换。

**武学装备/准备系统**：弟子可从已习得的武学中选择一门装备至对应技能槽位（术语使用「准备」而非「装备」）。切换准备不消耗回合，但切换后原槽位的修炼进度保留。准备面板以六列展示，每列列出该类可用的已习得武学，当前准备者高亮标记。

**高级武学瓶颈机制**：任何高级武学（杂役/外门/内门层）的等级不能超过其对应基础武学（basic_skill）的等级。例如，「太极拳」（内门拳脚，基础为「基本拳脚」）的等级上限等于弟子当前「基本拳脚」的等级。当弟子修炼接近瓶颈时（差值 ≤ 3），技能列表中以警示色提示。

**招架武学体系重做**：原设计中招架作为独立武学门类，每个门派生成通用招架武学（如「XX招架术」）。重做后：
- 所有拳脚类与兵器类武学均可用于招架，无需专门的招架武学
- 取消门派通用招架武学的生成逻辑，战斗门类从 5 降为 4（拳脚/轻功/内功/兵器）
- 仅保留少数具有专属命名的特殊招架武学：斗转星移（姑苏慕容）、乾坤大挪移（明教）、北冥神功（灵鹫宫）、吸星大法（日月神教）。这些武学的 `usable_for_parry` 标记为 true，可在招架准备下拉菜单中选取
- 前端招架准备下拉菜单：分为「拳脚武学」「兵器武学」「特殊招架」三组，按类别过滤可选武学
- 北冥神功为灵鹫宫镇派内功，兼通内功与招架（同时出现在 Force 和 Parry 准备选项中）
- 招架武学的历史模板数据（`SECT_MARTIALS` 中每个门派的招架名称）已统一清理，`tier` 元素从 5 个缩减为 4 个

**丹药体系**：武学类别枚举中添加 Knowledge 类（知识/医术），用于丹药制作与药理判定。丹药配方按功效分类（疗伤、回复气血、回复精神、提升内力、永久增益等），制作消耗草药资源与炼制时间。

### 弟子系统扩展

**弟子等级重构**：明确四级体系——杂役（入门弟子，无固定师长，从事杂务与外门劳作）、外门弟子（通过考核升入，可习外门武学，有固定师长）、内门弟子（门派中坚，可习内门绝学，可参与门派决策）、长老（门派柱石，可担任建筑主管，指导多名弟子）。弟子升降级由掌门手动任命，需满足武学等级和门派贡献条件。

**弟子个人属性面板**：展开状态下显示六类技能当前等级与经验进度、天赋五维（膂力/悟性/根骨/身法/福源）、状态资源（气血/精神/内力/精力）、当前行动与进度。面板顶部显示弟子姓名、年龄、等级、忠诚度。

**月度养成结算**：每月推进时，根据上月快照并行计算每位弟子（含 NPC 门派弟子）的行动效果。行动包括研读（消耗精神提升知识武学）、打坐（消耗气血提升内功）、冥想（消耗精神提升精力）、练功（消耗气血/精神提升拳脚/兵器/轻功）、切磋（与同门或外人比武获取经验）、外派（离派数回合后带回银两/声望/物品）、历练（离派数回合后随机触发江湖奇遇）。结算完毕后更新门派日志，产生对应的江湖纪事条目。

**弟子卡片折叠显示**：折叠态仅展示姓名、等级标签、当前气血/精神概览、进行中行动简写。展开态显示完整属性面板。卡片不直接显示武学名称（避免与装备/准备系统混淆），武学信息统一在属性面板的技能列表中查看。

**NPC 弟子只读卷宗**：玩家可通过门派关系界面查看 NPC 门派的弟子名录，展示方式与自家弟子面板一致但不可操作。NPC 门派掌门标注「掌门」头衔，兼任建筑的标注「掌门兼XX长老」。

### 门派经营深化

**七堂建筑职能**：门派建筑扩展为七个职能堂口——
- 传功堂：负责弟子武学传授与指导，长老可指定传授武学和受教弟子
- 藏经阁：存放门派武学典籍，管理公共书籍与私藏秘籍，支持武学研究（解锁新武学）
- 百草堂：炼制丹药与药膏，管理草药库存，长老可主持自动炼药或手动开炉
- 司库房：管理门派银两与物资收支，处理月俸发放与物资申领
- 庶务堂：负责建筑建造与修缮，消耗精铁、粮秣等资源升级各建筑
- 内务堂：管理内门仓库（兵器、护甲、武学秘籍等稀有物资）
- 外务堂：管理外门仓库（粮秣、草药、生活物资），处理弟子申领与物资调配

**建筑长老模型**：每堂可委派一名长老负责该堂事务。长老影响该建筑的产出效率（如百草堂长老炼丹速度翻倍，庶务堂长老大副缩短建造周期）。掌门可兼任某堂长老（显示「掌门兼XX长老」），掌门亲自操作时享有额外效率加成（如炼丹耗时减半）。

**门风方略系统**：掌门每月可调整门派的道德方略——正派（以德服人，弟子倾向于行侠仗义、声望增速快）、中立（顺其自然，各项均衡）、邪派（以力服人，弟子倾向于劫掠敛财、银两增速快但声望受损）。方略影响弟子的自主行动倾向和随机事件的触发权重。

**百草堂自动炼药机制**：掌门可设置一个循环炼药队列（按顺序指定药方），百草堂按月自动推进炼制。无长老时炼制速度为半速，有长老时全速推进，草药不足时自动暂停等待。掌门也可手动开炉单次炼制，耗时较常规缩短。丹药产出自动存入药库，可在物资管理中发放给弟子使用。

**门派资源系统**：新增两类门派资源——精铁（用于建筑建造与兵器铸造）和粮秣（用于弟子口粮与门派日常消耗）。每位弟子享有私银（每月月俸）和个人口粮配给。建筑维护每月消耗固定资源。炼丹额外消耗草药（从门派药库扣除）。弟子受伤后可自主从药库申领疗伤药物。

### 朝廷势力与门派交互

**朝廷势力重构**：原「朝廷」NPC 门派拆分为两大势力——
- 大元国下辖 **金帐汗国**（court）：以蒙古铁骑与满清朝堂为主体，行事霸道，崇尚武力，与大宋为敌对关系
- 大宋国下辖 **枢密院**（song_court）：以汉人官僚体系为主体，注重谋略与朝堂博弈，与大元为敌对关系

两国势力的弟子、武学、建筑各自独立，初始关系为敌对。门派交互中可根据玩家选择调整与两国的关系。

**门派交互事件**：每月推进时除常规弟子行动外，额外生成 3~5 条世界事件，涵盖：
- 切磋事件：NPC 门派弟子之间的比武切磋，胜者获得武学经验与声望
- 叛逃事件：低忠诚度 NPC 弟子可能叛投他派，目标门派获得新弟子
- 联盟事件：关系友好的门派之间可能结盟
- 朝廷征召：金帐汗国或枢密院可能征召其他门派弟子入伍或入朝
- 掌门更替：NPC 门派掌门可能因年老或战斗死亡而更替，继任者从长老中选拔

### 界面细节优化

**过月按钮迭代历程**：原按钮位于决策面板下方，后独立出来，历经多轮调整——去掉箭头符号 → 右对齐 → 与「本月尚可定夺 N 次」文本同行并排 → 贴右边缘。最终布局为：文本在左、按钮在右，整体靠右，按钮贴边。

**定夺次数显示**：从独立面板移至顶部属性栏第一行，直观展示本月剩余决策次数。

**中栏滚动条修复**：中栏内容溢出时产生水平滚动条，根因是 flex 容器 `min-height: 0` 未设置导致子元素撑开父容器。通过给中栏设置 `overflow-y: auto; min-height: 0` 并将内部 tab 内容设为 `flex: 1 1 0` 彻底解决。同步修复了中栏底部内容截断（最后一行被导航条遮挡）的问题。

**下拉菜单样式**：修复深色模式下悬停高亮不可见的问题（强制浅色背景），以及选中项的高亮样式缺失。

**建筑页面文案**：修复建筑标题与长老事务文字的横向重叠问题。统一传武授艺相关文案风格。

**技能术语**：将「装备」重命名为「准备」，更符合武侠语境（弟子「准备」某门武学迎敌，而非「装备」武器防具）。

### 数据库优化

**慢查询优化**：`list_games` 接口原先将 70 个存档的完整游戏状态 JSONB（每个约 200-500KB）全部拉取至内存，耗时 2.38s。优化方案是通过 SQL 侧的 JSONB 标量提取（`state->>'year'`、`state->>'month'`、`state->>'autosave'`），只拉取列表展示所需的三个小字段，将查询时间降至 80ms 以内（约 30x 提升）。

**PostgreSQL → SQLite 迁移**：由于游戏为单机桌面应用，无需 Client-Server 数据库，且 SQLite 单文件、零部署的特性更适合分发场景。迁移涉及：
- 表结构：`JSONB` → `TEXT`（存储 JSON 字符串），`TIMESTAMPTZ` → `TEXT`（ISO 8601 格式），`UUID` → `TEXT`，`BIGSERIAL` → `INTEGER PRIMARY KEY AUTOINCREMENT`
- SQL 语法：`gen_random_uuid()` → Rust 侧 `Uuid::new_v4()`，`now()` → `datetime('now')`，`ANY($1)` → 逐条绑定，`FOR UPDATE` → 去掉
- 连接池：`PgPool` → `SqlitePool`
- 配置：5 个 PostgreSQL 连接参数字段（地址/端口/用户/密码/库名）简化为单个 `db_path` 字段
- 已有 70 档存档、1540 条事件数据全部从 PostgreSQL 导出并导入至 SQLite，数据完整无损

迁移后性能对比：存档列表 84-135ms（原 PG 2.38s），单档载入 59-62ms（1MB payload），测试 54/54 全绿通过。

### 小说 NPC 体系

**静态 NPC 模板系统**：所有金庸小说中有名有姓的 NPC 角色均以静态模板（NamedNpcTemplate）定义，含固定年龄、天赋、技能等级、道德声望、门派职位等。创建新游戏时自动按门派填充，不进行读档迁移兼容。新存档只写模板生成的身份而不保存完整模板。

**NPC 职位系统**：NpcPosition 枚举（SectLeader/DeputyLeader/Elder/InnerDisciple/OuterDisciple/Chore/Wanderer）。职位固定不变。Disciple 新增 is_named_npc 和 npc_position 字段。小说 NPC 的年龄、天赋、道德、声望、武学造诣、技能列表均为固定值，仅当前气血/精神/内力/精力每月计算。掌门兼任传功堂，副掌门兼任外务堂。

**全量角色覆盖**：从 xkx100 + 金庸小说约 120 名角色，涵盖 24 个门派。武当 9 人、少林 8 人、华山 4 人、明教 6 人、全真 9 人、天龙寺 5 人、桃花岛 3 人、古墓 3 人、丐帮 3 人、峨嵋 3 人、日月神教 4 人、星宿 2 人、慕容 4 人、大轮寺 3 人、灵鹫宫 2 人、白驼山 2 人、雪山 2 人、天地会 1 人、神龙教 2 人、绝情谷 3 人、五毒教 2 人、青城派 3 人、金帐汗国 8 人、枢密院 10 人、散人 7 人。

**门派化长老称号**：sect_buildings() 按门派 ID 返回定制称号。武当真君/少林首座/明教左右使/丐帮长老/古墓侍/朝廷怯薛长等。玩家门派保持中性称号。

**NPC 专属江湖纪事**：generate_named_npc_chronicles 每月生成 1~3 条以小说 NPC 为主角的纪事。掌门有专属事件，约 35% 概率触发跨门派联动。

**门派填充策略**：每个 NPC 门派补充至少 2 名随机杂役弟子，使门派人数饱满。
